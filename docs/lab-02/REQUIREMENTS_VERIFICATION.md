## Section 4: Required Ticket Behavior & Business Rules (PDF §4.3)

All mandatory business rules documented:

### Ticket defaults & system-generated values
- [x] **BR-01** – Official Ticket Number generated by backend, format: TKT-{YYYY}-{6-digit sequence}
- [x] **BR-02** – New Ticket begins with Current Status = New
- [x] **BR-11** – IT Priority and Ticket Owner remain null (null) on Requester-created tickets

### Requester selection & switching
- [x] **BR-03** – Lab 2 uses Development Requester selector, testing-only, not authentication
- [x] **BR-21** – Selected requesterId persisted in sessionStorage only, sent via X-Dev-Requester-Id header
- [x] **BR-04** – Only active Development Requesters appear in selector
- [x] **BR-05** – Stale/inactive requester context clears sessionStorage, redirects to Selector
- [x] **BR-14** – Switching selected Requester clears cached ticket state and reloads

### Ticket ownership
- [x] **BR-06** – Ticket ownership fixed at creation, cannot be changed in Lab 2
- [x] **BR-24** – All endpoints enforce ownership server-side via X-Dev-Requester-Id; mismatch returns 404

### Search, filtering, sorting, pagination
- [x] **BR-22** – My Tickets defaults: page=1, pageSize=10 (max 50), sort=createdAt, order=desc
- [x] **BR-07** – Category and Related System selections must reference active records; stale IDs rejected with 409

### Validation & duplicate-submission prevention
- [x] **BR-08** – Ticket Summary required, trimmed, 5–120 characters
- [x] **BR-09** – Ticket Description required, trimmed, 10–2,000 characters
- [x] **BR-10** – Requested Priority required: LOW, MEDIUM, HIGH; defaults to MEDIUM
- [x] **BR-15** – Duplicate-submission prevention frontend-only (disabled/busy Submit button)

### Failure behavior & data retention
- [x] **BR-16** – On create failure, form values preserved, inline error shown, no auto-retry
- [x] **BR-17** – Ticket created successfully, attachment upload fails → ticket NOT rolled back, failure reported separately

### Attachment upload, download, soft removal
- [x] **BR-12** – Attachments optional; limits: ≤5 active per ticket, max 5MB per file, types JPG/JPEG/PNG/WEBP/PDF
- [x] **BR-13** – File type validated by extension AND content sniffing; invalid files rejected
- [x] **BR-18** – Removal is soft-delete only: sets isRemoved=true, removedAt, removalReason
- [x] **BR-19** – Removal requires explicit confirmation dialog; reason optional ≤200 chars
- [x] **BR-20** – Removed attachment remains visible as metadata; Download and Preview disabled
- [x] **BR-26** – Each attachment records: originalFilename, storedFilename, mimeType, fileSizeBytes, uploaderRequesterId, uploadedAt
- [x] **BR-27** – Uploaded files renamed to safe storage name (UUID + extension); original filename retained as display metadata only
- [x] **BR-28** – Attachment preview available for active (non-removed) attachments; images inline, PDFs first-page-only

### Inactive Requesters
- [x] **BR-29** – Inactive Requesters' existing tickets remain in database; not reachable in Lab 2 requester-facing flows

### Empty and no-results states
- [x] **BR-23** – "Empty" (zero tickets ever) vs "No-Results" (filters matched zero) use distinct messaging

### Transition to real authentication in Lab 3
- [x] **BR-25** – X-Dev-Requester-Id header is testing convenience only; Lab 3 must use authenticated session/token

**Mapped to:** `specification.md` §5 (Business Rules: BR-01…BR-29)
